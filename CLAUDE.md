# CLAUDE.md — project instructions

## Architecture

Read `DESIGN.md` first. It defines what belongs where and the invariants. All
decisions flow from it — chiefly: **pure Go, no CGO** (cross-compiles to Windows),
and **never corrupt a save** (read-only on open, atomic write, automatic backup,
game closed before writing).

## Working methods

- **Plan first.** Every change is planned before code, following
  `PROCEDURE_PLANS.md`. Plans live under `.claude/plans/` (`vX.Y.Z/` per release,
  `release/` for tooling), never at the repo root. See `.claude/plans/README.md`.
- **Hybrid git.** Work on a dedicated branch (`feat/…`, `fix/…`, `refactor/…`,
  `docs/…`, `chore/…`, `ci/…`, `build/…`), never on `main`. Commit atomically
  (Conventional Commits). **Never** merge, push, or tag — the user does that.
- **Releases.** SemVer, pre-1.0 (`0.x`): breaking changes bump the minor.
  `CHANGELOG.md` is generated by `git-cliff` (`just changelog`); pushing a `v*` tag
  triggers the release workflow.
- **Docs in the same commit** as the code they describe. A structural change without
  a doc update is a defect.

## Layers & scopes

```
internal/sqlcipher → internal/save → internal/web → cmd/dsa-save-editor
```

Lower layers never import higher ones. Commit scopes: `sqlcipher`, `save`, `web`,
`cmd`, `nix`, `docs`.

## Verification

```bash
nix develop --command just ci      # fmt-check + vet + lint + test + build
DSA_SAVE=/path/to/6144_Slot1.db just test   # also round-trips a real save
just build-windows                 # release-time cross-compile gate (.exe)
```

`just` is the single source of truth for the gates — pre-commit and CI call the
same recipes.

## Save safety

- Never write a save while the game is running (it holds the DB open).
- Real saves, `*.sav`, screenshots and backups are local fixtures — never commit
  them. Reference a real save through `DSA_SAVE`.
